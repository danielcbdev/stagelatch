# Rule reference

Every rule has an ID of the form `<check>/<rule>`. The same ID is used in the hook lists, in `rules:`, in ignore comments and in the baseline.

- **Change a severity** in `stagelatch.yaml`: `rules: { tests/new-skip: off }` (`error`, `warning` or `off`).
- **Suppress one finding** with a comment on its line or the line before: `// stagelatch:ignore <rule-id>` in Dart, `# stagelatch:ignore <rule-id>` in YAML.
- **Accept the findings a legacy codebase already has** with `stagelatch baseline create`.
- **`stagelatch/invalid-ignore`** (warning) is reported by the tool itself, not by a check, when an ignore comment names an unknown rule.

## `format`

Runs first and may fix files in the index.

| Rule | Default | Fix | Reports |
|---|---|---|---|
| `format/unformatted` | error | yes | A Dart file is not formatted. |

## `analyze`

Reports findings.

Reports the diagnostics of your SDK's analyzer, one rule per diagnostic code: `analyze/<analyzer code>`. Which ones block is set by `analyze.fail_on`.
