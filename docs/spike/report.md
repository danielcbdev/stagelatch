## 2. Candidates

- **A, embedded** (`probe_embedded.dart`): `AnalysisContextCollectionImpl`
  over an `OverlayResourceProvider`, `sdkPath` set to the project SDK, an
  on-disk `FileByteStore` in the `--cache` directory; `getErrors` per
  file with `ErrorProcessor` for `errors:` severities; `DartFormatter`
  with the package language version and the nearest `page_width`.
- **B, delegated** (`probe_delegated.dart`): the project SDK's
  `dart --suppress-analytics language-server --protocol=analyzer
  --cache=<dir>`; `analysis.updateContent` overlays, then
  `setAnalysisRoots` (the package), `setPriorityFiles`, `getErrors` per
  file sent immediately, `edit.format` per file, `server.shutdown`.
- **B, files as roots** (`delegated-files`): B with `setAnalysisRoots`
  given the files to diagnose instead of the package. Not in the plan;
  measured to see whether B's cost depends on the root.

## 4. Latency (official)

`dart run benchmark/bin/measure.dart --probe embedded --probe delegated
--probe delegated-files`. Each run is the activated `stagelatch_bench`
executable, timed by the caller from process start to exit; the scenario
is applied once per block. Cold: 3 runs, each with a fresh empty cache
directory, after one `dart --version`. Warm: 11 consecutive runs sharing
one cache directory, the first discarded, 10 kept. p95 is the nearest
rank (with 10 runs, the slowest). Phases are measured inside the process;
`read` is reading the index through `git cat-file --batch`. Raw data:
[`06-measurements.json`](../../benchmark/results/06-measurements.json).

| Probe | Scenario | Cold p50 | Cold p95 | Warm p50 | Warm p95 | Warm in-process p50 | Warm phases p50 (read / start / overlay / diagnose / format) |
|---|---|---|---|---|---|---|---|
| embedded | s3 | 14.93 s | 14.97 s | 2.73 s | 3.20 s | 1.86 s | 62 / 286 / 0 / 1374 / 88 ms |
| delegated | s3 | 15.18 s | 15.64 s | 14.59 s | 14.86 s | 13.60 s | 66 / 26 / 13383 / 17 / 31 ms |
| delegated-files | s3 | 13.67 s | 13.68 s | 13.10 s | 13.59 s | 12.12 s | 67 / 26 / 11599 / 16 / 316 ms |
| embedded | s10 | 15.18 s | 15.23 s | 2.69 s | 3.21 s | 1.85 s | 61 / 287 / 0 / 1367 / 127 ms |
| delegated | s10 | 14.27 s | 14.45 s | 13.60 s | 14.11 s | 12.78 s | 61 / 25 / 12465 / 39 / 139 ms |
| delegated-files | s10 | 12.90 s | 13.17 s | 11.64 s | 12.66 s | 10.80 s | 61 / 25 / 10190 / 40 / 363 ms |

Startup of the activated executable with no arguments (usage only), 10 runs: p50 0.81 s, p95 0.85 s.

The startup line is the fixed cost of the distribution path: `pub global
run` of a path-activated package resolves it and starts the JIT snapshot
before `main` runs. It is part of every total above.

Where B's time goes: almost all of it is the response to
`analysis.setAnalysisRoots` (the `overlay` phase above), with or without
a warm cache. The server's cache stays at about 6 MB of unlinked
summaries, while A's byte store reaches 127 MB and makes A's warm
`diagnose` about 10 times faster than its cold one. B's fixed cost on
Flutter is visible outside this spike too:

| Root given to a fresh server | `setAnalysisRoots` |
|---|---|
| stagelatch (Dart only, about 150 files) | 1.0 s |
| a 16-file Flutter package of the corpus | 5.1 s |
| the corpus package | 13.2 s |

`dart analyze` of the SDK on that 16-file package takes 4.1 s with the
user's own warm server cache.

## 5. Parity

`dart run benchmark/bin/parity.dart`, against an oracle that exports the
index (`git write-tree`, `git archive | tar -x`), and runs the SDK's
`dart analyze --format=json` and `dart format --output=json` there.
Diagnostics compared as `(path, code, severity, offset, length)`,
formatting byte for byte. Full output:
[`04-parity.md`](../../benchmark/results/04-parity.md).

| Probe | Corpus s3 (3.47.8) | Corpus s10 (3.47.8) | Fixture s3 (3.44.9) | Fixture s10 (3.44.9) |
|---|---|---|---|---|
| A, embedded | 2 differences | 3 differences | 2 differences | 2 differences |
| B, delegated | 0 | 0 | 0 | 0 |
| B, files as roots | 0 | 0 | 0 | 0 |

Every difference of A is a missing lint (`directives_ordering`,
`prefer_const_constructors`). Lint rule implementations ship inside the
SDK (`pkg/linter`); `package:analyzer` on pub.dev has none, and the
`linter` package on pub.dev is discontinued at 1.30.1 (Dart 2). Errors,
warnings and formatting matched. A also names one error differently from
the SDK (`undefined_instance_member_read` against `undefined_method`, seen
on the trap).

The corpus cannot be re-resolved on Flutter 3.44.9 (its dependency `qr`
needs Dart ^3.13), so the older SDK runs on the fixture, as the plan
allows.
